Session

One call, four tools, no live campaign

Pick a time on signup, then run this order. Each step has its own page. Stop when the procedure is proven or broken. Do not start a real adventure.

This round is for a trusted group. This site never stores AMBA, WG, Owlbear, Discord passwords, or the GM API key. The shared time grid shows handles, not emails.

1. Discord

Everyone joins the same voice channel. The GM screen-shares AMBA and keeps that share. Players have WG open on their own machines. Then Owlbear when that step starts.

2. GM campaign in AMBA, players in WG

The GM creates the campaign in AMBA and connects with the API key there. They do not log into WG. Players follow AMBA WG: own login at WGUI, one test character, join key from Discord (not the API key). Confirm each player’s WG view matches what the GM expected from AMBA.

Example

Four handles are on the call. GM stays in AMBA. Each player says their character name from WG. If one name never appears, they retry once with their own WG account, then we note it and continue with three. Nobody shares the API key.

3. Sample encounter

Pick a small monster set in AMBA. Fire one attack and one DC from AMBA; players resolve what they can see in WG. Talk out loud about who can click what.

4. Owlbear scene

GM sends the room URL from Owlbear. Players ask to join and wait. Place tokens. Move one PC token. If export did not bring monsters over, place two by hand so the permission test still happens.

5. Write it down

End on feedback with what worked, what blocked, and whether the next run should be one longer call or two shorter ones.
