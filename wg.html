    Have a character on Pathbuilder?

    Bring it into WG with WG’s own importer. Do not drop a Pathbuilder file on Uploads—that page only takes WG JSON.

    1. In Pathbuilder 2e, open the character, use the menu, and choose Export JSON. Pathbuilder gives a six-digit id (it hosts the JSON; you paste the id, not a file).
    2. In the new UI, open Characters (wgui.wandersguide.site).
    3. Open the import menu next to Create Character (upload icon). Choose Import from Pathbuilder.
    4. Paste the six-digit id and import. That creates a WG character on your account.

    Then treat it like any other WG PC: turn on Public Character, export WG JSON, and drop that file on Uploads. You still need two characters that are not twins—import a second Pathbuilder PC or build the other one in WG.

    Public Character — old UI and new UI

    Turn on Public Character for both PCs so anyone with the sheet link can open them—the equivalent of a public Pathbuilder share, not a locked Foundry actor. Same label in both UIs; different clicks to get there.

    • Old UI: Open the character in the builder (/builder/…). Use the Home step (house icon, first stepper step). Open the Options tab (last of Books, Homebrew, Variant Rules, Options). Switch on Public Character (after Organized Play, before Voluntary Flaw).
    • New UI: Open the character builder (sheet with ?view=builder, or Characters → that PC). Stay on the Home step (not Builder). Open the Options tab. Switch on Public Character.

    Use old UI, new UI, or both for building. Do not skip the public switch.

    Before the call

    Sign in with your own WG account. Create two characters that are not twins. Make both public. Export each character’s WG JSON. Then drop both files on Uploads. Do not log into AMBA. Do not ask for the GM API key.

    Example

    Merry-Anchor builds a scout in old UI and a cleric in new UI, turns on Public Character on both (Home → Options), exports both, and drops them on Upload.

    When the group meets

    When we first meet on Discord, pick four of the eight to play. The GM then downloads those four from Uploads and imports them as PCs in the AMBA module, then creates the WG campaign and posts the join key. Enter the key in the new UI. That makes you available for the campaign. You should not appear under Characters on the GM’s WG account—that list is the GM’s characters if AMBA is linked. You should appear on the Party bench in encounters. The four leftover files stay unused for this run.

    What the GM does (still in AMBA)

    After Discord pick, download the four chosen JSON files from Uploads. Import them as module PCs. Link WG from the AMBA avatar menu (Settings → Wanderer's Guide), then Create campaign in the module’s WG settings and post the WG join key in Discord. Combat is designed and fired from AMBA. Players watch and click in the new UI only.

    Example

    GM, still in AMBA: “Join key is in the pin. Paste it in WGUI. Check the Party bench, not Characters.”

    Combat and skill — new UI only

    On the call, open the new UI (wgui.wandersguide.site). Leave the old builder. The table designs a moderate XP encounter and one skill in AMBA. Confirm the four chosen PCs on the Party bench. Combat notes stay in the new UI, not on the map.

    If the bench is empty

    Joined players may not show on the Party bench in every encounter, and the API may not update WG in real time. If they never show, mention it on feedback and continue to Owlbear with tokens placed by hand if needed.
