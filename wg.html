AMBA WG

Players log in here. The GM does not.

AMBA WG (Wanderer’s Guide UI) is the player campaign layer. Each player signs in, picks one test character, and joins with a key. The GM stays in AMBA and uses an API key there. Nobody shares passwords or the GM API key.

Players open wgui.wandersguide.site. The GM keeps AMBA on the Discord share so the table can see GM actions. Do not expect a GM WG login.

What the GM does (still in AMBA)

The GM does not log into WG. After the campaign exists in AMBA and the API key is set, they post the player join key in Discord if one is required. Combat and DC checks are triggered from AMBA over the API. Watch player WG screens to see what actually appeared.

Example

GM, still in AMBA: “Join key is in the pin. Use WG, not AMBA. I will start the goblin round from here.” They never open WGUI as themselves.

What a player does

Sign in at WGUI with your own account. Create or select one disposable test character. Enter the join key from Discord. Say what you see: “Scout is in” or “I only see a blank prompt.” If something is missing, put it on feedback. Do not ask for the GM API key.

Example

Merry-Anchor signs into WG, makes a level-1 test scout, pastes the join key, and says “Scout is in.”

Combat and DC (tiny)

One player character vs one monster the GM already set up in AMBA. The player takes one attack or save in WG when the GM fires it from AMBA. Then one DC check, same split: GM in AMBA, player in WG. Compare screens. Stop.

What we still do not assume

Whether the API updates WG in real time, and which buttons a player can press, is the point of the test. If stats never show, record it and continue to Owlbear with tokens placed by hand if needed.
