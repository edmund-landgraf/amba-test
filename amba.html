AMBA

GM creates the campaign here

AMBA is GM-only. The GM logs into AMBA, creates the campaign, and talks to Wanderer’s Guide through an API key. The GM does not log into AMBA WG.

Screen-share AMBA so the table can watch prep. Players never get an AMBA login and never get the API key. This signup site does not store that key.

What the GM does

Sign in to AMBA. Create or reopen the workflow-test campaign. Put the WG API key into AMBA (not into Discord, not into this site). Use AMBA to drive campaign state over that API: roster, encounter, combat, DC checks. Post a player join key in Discord if WG needs one. That join key is not the API key.

Example

GM opens AMBA, creates “Workflow Test 1”, pastes the API key into AMBA’s integration field, adds two goblins. In Discord: “I am staying in AMBA. You join WG with your own accounts. API key stays on my machine.”

What players do

Nothing in AMBA. They use AMBA WG only.

What we are trying to learn

Whether campaign create, API-key setup, and GM-side controls in AMBA are obvious, and whether WG and Owlbear update when the GM acts from AMBA.
